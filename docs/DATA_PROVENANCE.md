# Data Provenance and Commercial Use

## Purpose

ModelJudge AI can produce structured evaluation records, but software ownership and dataset ownership are separate questions. Every commercial release must have a traceable provenance record.

## Required provenance fields

For each release, maintain records for:

- task/prompt origin
- response origin and generating model/provider where applicable
- annotation/reviewer identity or controlled reviewer identifier
- evaluation timestamp
- dataset/release version
- external source URLs or source identifiers where applicable
- applicable license or permission
- transformation or preprocessing performed

## Demo data

Repository demo records are illustrative evaluation examples. They are provided to demonstrate application behavior and should not be treated as proof of ownership of a production dataset.

## Commercial release gate

Before selling, licensing, or redistributing an evaluation dataset, confirm that the release contains only material for which the operator has appropriate rights or permission. Review model-provider terms, source licenses, privacy requirements, contractual restrictions, and any applicable data-protection obligations.

## Quality evidence

Quality, reliability, calibration, and reviewer metrics describe the evaluation process. They do not establish copyright ownership, factual correctness of every response, or unrestricted commercial redistribution rights.

## Buyer responsibility

A buyer receiving the software must perform its own legal/provenance review before creating a commercial dataset. The platform provides technical controls and evidence; it does not replace legal review.
